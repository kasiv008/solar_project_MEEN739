# Siting solar on the Texas A&M campus: inventory, design and portfolios

MEEN 439/739 Solar Energy Engineering, Team 4 (Felipe Martinez, Kasi Viswanath, Vildan Turan,
Ahmet Kutay Aydogan).

This repository is a reproducible pipeline for the **main College Station campus**: a 3 km × 3 km tile
(RELLIS and the farms are out of scope). Its steps:

1. **Inventory:** every TAMU rooftop, garage top, surface parking lot and open-land tract, screened by
   ownership, type and size.
2. **Measurement:** each site is measured from LiDAR (roof planes, obstacles, setbacks, trees) and
   checked against the 30 cm imagery.
3. **Shading and SAM inputs:** per-site shading from LiDAR horizons and the College Station TMY,
   written as PySAM (PVWatts v8) inputs.
4. **Energy:** PySAM run for all 1,062 sections.
5. **Design sweeps:** tilt, ground coverage ratio (GCR), fixed vs. tracker and DC/AC, inside a
   practical envelope.
6. **Portfolios:** least land, least cost, maximum output and grid-limited, each scored hour by hour
   against the FY2026 campus load.

Everything runs for **two LiDAR surveys kept separate**: 2017 (USGS 3DEP) and 2025 (TNRIS StratMap).

## Quick start

```bash
git clone <this repo> solar_project && cd solar_project

# 1. environment (conda-forge, ~5 min)
conda env create -f environment.yml
conda activate solar

# 2. data: unzip solar_data.zip in the repo root (creates tamu_land_resources/ and data/raw/)
unzip solar_data.zip

# 3. run everything (~10 min, both LiDAR years)
./run_all.sh            # or: ./run_all.sh 2025   for one vintage
```

To run a single step without activating the env, use `./run.sh scripts/<step>.py --vintage 2025`.
`run.sh` finds `<conda base>/envs/solar`; set `SOLAR_ENV=/path/to/env` if your env lives somewhere else.

|---|---|---|---|
| 01 | `01_fetch_tamu_layers.py` | Downloads all 58 TAMU FCOR basemap layers for the tile. The server is flaky with no paging, so it fetches by object ID with retries; re-runs fetch only incomplete layers. | `data/raw/tamu_fcor.gpkg` |
| 02 | `02_screen_footprints.py` | Screens TAMU University Buildings: ownership, type, open-air venues, construction, ≥ 500 m², in the tile. Builds open land as Main Campus minus buildings, pavement, parking and water. | `data/interim/inventory_step1.gpkg`, `outputs/step1_roofs_vs_v2.csv` |

| 04 | `04_roof_geometry.py --vintage v` | Per roof: plane fit → tilt, aspect and roughness; flat and pitched segments; obstacles (> 0.3 m off the local roof); 1.2 m edge setback; usable mask. Open land: canopy and slope. | `data/interim/<v>/inventory_step2.gpkg` |
| 05 | `05_shading.py --vintage v` | 36-direction horizons (buildings + trees) plus TMY → annual shade loss per m²; cells losing > 20 % dropped. | 06 | `06_qa_imagery.py --vintage v` | Footprint vs LiDAR overlap (IoU) and offset; imagery review pack | `outputs/<v>/qa/` |
| 07 | `07_parking.py --vintage v` | Carport canopies over the painted stall rows (TAMU Parking Line); trees removed; shading from canopy height | `outputs/<v>/parking_lots.csv`, `parking_sections.csv` |
| 08 | `08_pysam_batch.py --vintage v` | PVWatts v8 for every section and tract, each with its own shading | `outputs/<v>/energy_sections.csv`, `energy_hourly_mw.csv` |
| 09 | `09_campus_balance.py --vintage v` | PV vs (campus load − CHP) hour by hour, FY2026 low / central / high | `outputs/<v>/campus_balance.csv` |
| — | `compare_vintages.py` | 2017 vs 2025 per roof | `outputs/compare_2017_vs_2025.csv` |
| 10 | `10_design_sweeps.py`, `plot_design_sweeps.py` | Roof tilt, GCR and east-west racks; carport tilt and azimuth; fixed vs tracker GCR; DC/AC at fixed AC; practical envelope flagged | `outputs/design_sweeps/` |
| 11 | `11_portfolios.py --vintage v`, `plot_portfolios.py` | Portfolios: A least land, B least cost (B1 without Polo Fields, B0 no open land), C maximum output (C0 built land), D grid-limited. ## Mount types and cost drivers
| Archetype | Where | Mount / structure | Cost key |
|---|---|---|---|
| `roof_flat_rack` | flat roofs | ballasted 10° rows (east-west 5° as the land-limited option), no penetrations | roof |
| `roof_flush_pitch` | pitched faces facing E through S to W, 10–45° | flush rails at the face's tilt and azimuth | roof |
| `garage_top_canopy` | garage top decks | elevated steel canopy (the deck stays in use); structural review | carport |
| `carport` | surface lots, over the stall rows (aisles open) | steel T-canopies, 7°, 0.18 kW per m² of canopy | carport |
| `ground_fixed` / `ground_tracker` | open land | driven piles, fencing, site prep | ground |

Each site carries `height_m`, `roof_age_yr`, `dist_substation_m`, `system_capacity_kw` and placeholder capex.

## Feeding PySAM (PVWatts v8)
One row of `outputs/<v>/roof_sections.csv` (or `parking_sections.csv`) is one PVWatts system:
- `system_capacity = system_capacity_kw`, plus `tilt`, `azimuth`, `gcr`, `array_type`
- `losses = 11.42` (the PVWatts defaults without the generic 3 % shading)
- `shading_en_azal = 1`, `shading_azal = json.loads(shading_azal)`, `shading_en_diff = 1`, `shading_diff`

**PySAM 7 silently ignores shading tables unless the `shading_en_*` flags are set.**
Roof racks: PVWatts "roof mount" has no row-to-row shading, so `08` applies a derate from open-rack runs.
Canopies are modelled as continuous planes. Sections ending in `-E01` are estimates for roofs the
vintage does not show.

## Known limits
- **LiDAR dates:** the 2017 LiDAR (not 2019, as the progress report says) misses 21 roofs built since then; the 2025 run estimates 11 roofs with no building points.
- **Tree shading:** both surveys are leaf-off (January), so deciduous tree shading is under-estimated. Live oaks are evergreen.
- **Open land:** an upper bound. The policy screen removes parks, rec fields, golf, gardens and research farmland, but not future building sites, which no public layer shows.
- **Costs:** placeholders. There is also no public hourly campus load, so the load shape is a flat or cooling-driven proxy calibrated to annual totals.
